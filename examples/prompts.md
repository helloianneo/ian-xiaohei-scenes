# Prompt Examples

下面这些 prompt 可以直接复制到 Codex 里使用。

## 只做配图规划

```text
Use $ian-xiaohei-scenes 先不要生图。
请分析下面这篇中文文章哪里适合做“小黑 + 真实物件 + 物理动作”的正文配图。
输出 5 张左右的 shot list。

每张图写清楚：
- 使用哪张母版
- 图的主题
- 读者共鸣点
- 物理动作
- 真实主物件
- 小黑在做什么
- 中文短标签
- 为什么这张值得画

<粘贴文章>
```

## 直接生成标准正文配图

```text
Use $ian-xiaohei-scenes 把下面这篇文章生成 4 张小黑实物场景正文配图。
要求：16:9 横版、纯白 #FFFFFF 背景、真实物件、小黑参与核心动作、2-4 个中文短标签。
每张图只讲一个物理冲突，不要做 PPT 信息图，不要截图，不要商业海报。

<粘贴文章>
```

## 单个观点生成一张图

```text
Use $ian-xiaohei-scenes 为这个观点生成一张 16:9 正文配图：

已读不等于完成，很多工作只是从聊天框里掉到了你桌上。

画面要像真实白色摄影棚里的小现场。
小黑必须承担核心动作。
中文标签最多 3 个，短一点。
```

## 彩蛋模式：长卷故事图

```text
Use $ian-xiaohei-scenes 的彩蛋模式，把这个项目复盘做成一张超横版长卷故事图。

主题：从一个小工具想法，慢慢变成有人愿意付费的小产品。
节点：想法、原型、测试、反馈、第一次付费、打包、持续维护。

要求：
- 使用小黑长卷故事图
- 一条手绘曲线路径
- 5-8 个真实物件节点
- 每个节点都有小黑动作
- 不要编号，不要时间轴信息图
```

## 产品演化长卷

```text
Use $ian-xiaohei-scenes 彩蛋模式，为“把混乱客服问题养成一个 AI 助手”生成一张长卷故事图。
从“重复问题太散”开始，到“每周用真实问题喂养助手”结束。
真实物件要轻，不要聊天 UI，不要 app 截图。
```

## 生成一组风格样片

```text
Use $ian-xiaohei-scenes 随机生成 6 个不同主题的小黑实物场景正文配图效果。
主题覆盖：会议拉扯、消息过载、生产报警、审查返工、AI 自动化、机会筛选。
每张单独生成，不要拼成一张。
```

## 改图：减少文字

```text
Use $ian-xiaohei-scenes 这张方向对，但文字太多。
请保持真实物件和小黑动作不变，减少到 3 个中文短标签。
背景仍然保持纯白，别变成海报或信息图。
```
